## 01 项目背景

企业内部资料分散在文档、Wiki 与历史沟通记录中。业务成员知道信息“可能存在”，却很难快速定位最新版本，也无法判断通用大模型给出的答案是否可靠。

项目通过 RAG 将自然语言问答与原始资料连接，在提升检索效率的同时，为答案提供来源依据和可追溯路径。

## 02 用户问题

### 用户画像

- 需要频繁查询流程、产品与业务规则的一线员工
- 负责维护内部知识的运营与管理人员
- 对回答准确性和权限边界有明确要求的企业团队

### 关键痛点

1. 关键词检索依赖用户知道文档名称与内部术语。
2. 相似文档版本过多，用户难以判断哪一份有效。
3. 大模型回答缺少引用时，业务人员不敢直接使用。

## 03 产品设计

产品体验围绕“提问、验证、继续行动”展开。答案不是终点，用户需要快速看到来源、定位原文，并在信息不足时理解系统为什么无法回答。

### 核心流程

1. 用户输入自然语言问题。
2. 系统识别意图与权限范围。
3. 检索相关文档片段并进行重排。
4. LLM 基于证据生成答案和引用。
5. 用户查看原文、反馈答案或继续追问。

## 04 AI 技术方案

| 层级 | 技术 | 关键指标 |
| --- | --- | --- |
| 文档处理 | Chunking / Metadata | 片段完整性与版本信息 |
| 检索 | Embedding / Hybrid Search | Recall@K |
| 重排 | Reranker | 相关性与证据覆盖 |
| 生成 | LLM | 忠实度与引用准确率 |
| 反馈 | 用户标注 | 有用率与失败类型 |

### 数据流

企业文档 → 清洗与切片 → 向量化 → 权限过滤 → 混合检索 → 重排 → LLM 生成 → 来源引用

当检索证据不足或来源冲突时，系统优先返回限制说明，而不是强行生成完整答案。

## 05 MVP 实现

MVP 覆盖文档导入、自然语言问答、来源引用和基础反馈，主要验证检索召回、答案可信度与业务使用效率。

- 文档切片保留标题、更新时间和来源路径
- 回答中的关键结论关联原始片段
- 对无答案、答案过期和权限受限分别处理
- 记录点赞、点踩与问题类型用于后续评估

## 06 产品迭代

### V1 可用问答

验证高频业务问题的检索与引用准确性。

### V2 评估体系

建立离线测试集与线上反馈面板，区分检索失败、生成失败和知识缺失。

### V3 业务工作流

从知识问答扩展到流程引导、表单填写与任务执行，同时保留权限和人工确认节点。

## 07 思考总结

RAG 产品的核心不是“能回答”，而是让用户知道答案来自哪里、何时可信、什么时候需要回到原始资料。产品设计需要把模型的不确定性转化为清晰的界面状态和下一步行动。
